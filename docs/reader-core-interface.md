# 阅读核心 Interface 审查

2026-11-14。研究库、阅读核心和展示三项职责已获用户确认。本文件展开阅读核心的候选 Interface，落实已确认的阅读行为；方法形状与内部组织供继续审查，尚未修改生产代码。总体方案见[技术方案提案](display-app-technical-plan.md)，产品要求见 [GitHub 规格 #3](https://github.com/GRHISMY/InvestmentShowcasePlatform/issues/3)。

## 阅读核心应让页面少知道什么

页面取得可直接呈现的内容、可用链接和导航状态，发出明确阅读意图。研究版本、关联解析、来源历史、位置恢复及记录资格由核心处理。调用者不必先保存来源、查找证据、拼 PDF 路径，再自行排列操作顺序。

## 创建时的输入与输出

只有研究库创建阅读器，普通页面不调用其构造入口。

| 契约 | 含义与所有权 |
| --- | --- |
| `ReadableStudy` | Reading 定义的输入：精确研究身份、已验证内容、固定版本资源访问值。Shelf 准备并提供，Reader 与 PDF 任务共享同一版本 |
| `RestoreCandidates` | 本版本内的主阅读、详情及 PDF 位置候选。Shelf 排序并为每条候选标记 `isLocalDevice`；Reader 检查语义位置，本机可恢复段落内偏移，远端仅恢复内容锚点，未标来源默认按远端处理 |
| `ReadingCheckpoint` | Reader 产生的实际阅读观察，保留发生时间；当前主动浏览的位置即使坐标相同也能更新时间，未被本次浏览涉及的其他位置项保留原时间 |
| 记录接收函数 | Reading 定义输出契约，Shelf 接收并增加设备序号，更新本机候选、串行保存和异步同步；不将接收或落盘时间改写成阅读发生时间 |

Reader 不导入 Shelf 或 iCloud 类型。Shelf 对 Reading 的依赖和注入记录函数的运行时回调不是双向代码依赖。没有任何一个页面需要自己协调记录存储。

## 页面可用的 Interface

| 操作或输出 | 具体含义 | 核心负责隐藏的规则 |
| --- | --- | --- |
| 当前阅读视图 | 内容、当前版本、访问身份、可用操作、恢复位置和提示 | 同一结果中的内容与导航状态保持一致，页面不能修改底层历史 |
| `selectFocus(choice)` | 选择同一图中的内容 | 验证图与焦点归属，原地更新说明和限制，不增加返回层级 |
| `switchMode(mode)` | 普通切换图解或报告 | 恢复目标方式上次位置；首次打开则使用该方式有效起点 |
| `follow(link)` | 明确查看某处关联内容 | 定向到该链接目标并保存来源；多个关联由读者选择，不自行取第一处 |
| `advanceMainline()` | 从当前图解内容沿带读主线前进 | 不读取返回历史来猜下一节，末尾保留最后内容并提供后续去向 |
| `back()` | 回到实际来源 | 恢复当时的模式、场景、焦点和正文位置，不通过关联反查猜测来源 |
| `openCitation(target)` | 核对指定引用 | 解析正确文件并定位引用物理页，初次自动定位不覆盖已有 PDF 续读位置 |
| `continuePDF(document)` | 继续读完整 PDF | 恢复该版本、该原件最近实际浏览的位置；没有记录则使用有效起点 |
| `enlargeDiagram()` | 放大查看同一张图 | 共享图与选中焦点；关闭后保留当前焦点和主阅读位置 |

上述操作按意图区分，而非把不同政策塞进一个通用 `open` 的隐含参数里。`follow` 的目标包括图解、报告、解释、计算和依据，不包括 PDF 引用；引用只通过 `openCitation` 进入，两条公开路径不会各自实现引用规则。

阅读视图同时提供前进、返回和切换方式的可用状态。带读前进不等于 PDF 翻页；不可用动作保持当前内容并给出清楚结果。研究库导航由 App 的共用宿主处理，Reader 管理研究内部的阅读来源，不依赖研究库界面。

## 只给共用宿主的观察 Interface

```text
reportVisiblePosition(observationToken, position, cause)
dismissPresentation(presentationToken)
```

`dismissPresentation` 只在原生关闭或返回手势已经完成时提交，复用核心同一套返回规则。取消手势不提交；迟到关闭不再作用于新的呈现，不产生第二次返回。它是共用平台宿主接入，不是普通页面需要协调的业务步骤。

`observationToken` 由核心发出，绑定当前版本、访问及内容观察范围；宿主只原样带回。旧页面退出、旧焦点排版或已经关闭 PDF 的回调不能覆盖新位置；位置保存确认等无关变化也不应让仍有效的观察失效。

`position` 是内容位置，例如段落锚点、计算输入、依据或 PDF 物理页。`cause` 只描述用户主动浏览、程序定位、恢复定位等事实。展示不发送“覆盖 PDF 续读”或“推进主线进度”这类政策结论，由 Reader 结合阅读意图决定记录哪些变化。

用户主动打开内容后，宿主确认对应内容已显示，再形成实际位置；单纯恢复、自动引用定位和同步重放不生成新的实际阅读时间。主动回看即使停在相同锚点或物理页，也能刷新本次浏览位置的时间；未被本次实际浏览涉及的其他位置项保留原时间。去重不能仅以“位置坐标相同”为依据。

位置观察只在共用阅读容器及 PDF/全屏图宿主中接入，图解、报告、计算等页面不用各写一套 `onDisappear` 保存或读取本机设置。

## 完整调用链

### 继续原版本并恢复主阅读

1. 读者选择继续阅读。Shelf 固定这次打开的原版本，即使准备中又出现新版也不换目标。
2. Shelf 提供完整可读研究和本版本位置候选；原版本暂不可用时提供准备或重试，不创建半可读 Reader，也不改开最新版本。
3. Reader 验证位置。较新候选无效时继续尝试同版本较早候选；焦点失效可保留有效场景，全部失效时回该版本全貌并说明。
4. 输出最后的主阅读方式和位置，保留详情及 PDF 的独立位置。启动不会自动弹出上次最深的详情。
5. 远端记录和新版只改变 Shelf 的下次打开候选，活动 Reader 保持原处。

### 图解到计算、PDF，再返回

```text
图解第八节／焦点 A／正文位置 X
  → follow(计算链接)
计算／输入位置 Y
  → openCitation(第二十九页引用)
PDF 自动定位第二十九页，旧续读第五十页保留
  → 读者主动翻页到第三十五页
PDF 续读更新为第三十五页，引用目标仍是第二十九页
  → back()
计算／输入位置 Y
  → back()
图解第八节／焦点 A／正文位置 X
```

再次明确核对该引用仍先到第二十九页；选择 PDF 续读则到第三十五页。在一次访问内自动重新定位引用页也不覆盖第三十五页续读记录。通过来源历史返回已有 PDF 访问时恢复那个访问的实际位置，与新发起一次引用核对不同。

PDFKit 负责显示指定文件和页，回报可见变化原因；是否更新续读由 Reader 的原文规则处理。用户从任何 PDF 入口主动浏览后，都可更新该原件的续读位置，入口页面无需知道这一政策。

### 图解、报告的切换与关联

假设图解停在问题 A，完整报告上次停在判断 P：

- 普通 `switchMode(报告)` 回到 P，不替读者选择 A 的某条相关判断。
- `follow(A 对应判断 Q 的链接)` 明确进入 Q，返回时回到 A 的实际来源位置。
- Q 对应多处图解时输出完整选择列表，选中 B 才进入 B；返回仍回 Q。
- 没有图解对应的判断正常保留完整报告阅读，合法的无图解研究也不需要伪造图解位置。

这组区别来自用户已确认的意图，不由页签、按钮或弹层技术暗中决定。

### 跨设备恢复最近实际位置

设备 A 原来停在第八节，设备 B 后来主动回看第三节：

1. Shelf 的记录实现接收 B 的记录，按发生时间和设备序号检查、去重并排列候选，不按文件到达时间推断。
2. A 当前打开的 Reader 保持原处，候选只影响下一次继续阅读。
3. 读者下次继续时，Shelf 取得候选对应的精确版本，Reader 检查第三节位置是否适用。
4. 有效则回第三节；焦点无效时保留有效场景并采用有效默认焦点，整条位置无效时继续检查同版本较早候选。
5. 报告、计算、依据和 PDF 位置独立恢复，第三节的新记录不会给未变化的旧 PDF 位置重新盖时间。
6. 恢复及同步重放不产生新的阅读发生时间，之后的主动操作才形成新的位置变化。

设备离线且时钟偏差的降级沿用总体提案：保留各设备有效候选，不宣称普通文件同步能证明绝对物理先后。

如果 A 在 B 回看第三节之后，又主动浏览原来的第八节，即使 A 的段落锚点没有变化，也应将 A 的第八节更新为最近实际位置；不能因坐标未变而丢掉这次阅读。

## 原地选择与全屏图

同图依次选 A、B、C 只更新焦点和对应说明，不形成三层返回历史。来源快照在明确进入另一处内容时捕获。

全屏图是同一图的查看状态，不另造一份图形、焦点或研究地址。放大后选择 B，关闭时主阅读保持 B；平移缩放属于展示视口，不能因关闭全屏而用旧快照覆盖新的焦点。

## 内部修改位置与验证

| 要改的规则 | 阅读核心内部位置 | 验证通过哪个外部行为 |
| --- | --- | --- |
| 跳转、前进、返回与末尾 | 阅读导航 | 调用后观察当前内容、焦点、前进与返回状态 |
| 多处图文关联、零处关联 | 内容关联解析 | 当前内容给出的目标集合及定向进入结果 |
| 引用与 PDF 续读 | 原文打开规则 | 自动定位不盖续读，主动翻页更新，返回保留来源 |
| 恢复位置与过期回调 | 阅读位置检查及观察接入 | 无效候选回退，旧页面回调不改变新内容 |
| 记录保存与云交换 | Shelf 内部记录实现 | 受理、串行落盘、重试与同步；不重新解释场景与焦点 |

Reader 是深 Module 的对外入口，内部仍由这些具体实现协作，不将所有条件写进一个庞大的类。已有读取器直接作为具体依赖使用；图文与核对规则的测试跨 Reader Interface，平台 PDF 回调和布局另做集成验证。

本文件为接口审查文档，不是已编译的实现；App 生产代码和参考样本未改动。

# 展示 Interface 审查

2026-11-14。展示的职责是把研究内容清楚呈现，并将真实交互交给阅读核心。本文件落实已确认参考样式与阅读行为，具体页面、菜单和弹层形式仍由实现与体验评估确定。总体见[技术方案](display-app-technical-plan.md)，阅读语义见[阅读核心 Interface](reader-core-interface.md)。

## 消费什么，交回什么

展示消费 Reader 产生的有限、具类型阅读视图：当前版本、有效访问身份、可读内容、有效链接、导航可用状态及恢复位置。它不按 ID 重新寻找判断和证据关系，也不扫描固定 Bundle 目录。

共用宿主接入 Reader。具体图解、报告、解释、计算和依据视图只做排版并调用既有具名动作；不各自保存一份当前场景、来源历史或阅读记录。

| 内部职责 | 处理什么 | 不承担的语义 |
| --- | --- | --- |
| 共用阅读宿主 | 纵向排版、动态字体、文字选择、可访问性、位置观察与恢复、系统返回适配 | 选择研究版本、拼来源历史、推断最新阅读位置 |
| 图形呈现 | 节点坐标、连线与标签、点击区域、自然尺寸、视口 | 重新选择研究主体、关系或财务数字 |
| 同图全屏 | 缩放、平移、适应视口，复用同一图及焦点 | 第二份图解和第二份语义焦点 |
| 共用详情 | 长解释、计算输入与限制、依据与全部引用入口 | 重算财务结果、固定只取第一处来源 |
| PDFKit 宿主 | 本版本文件加载、物理页换算、适宽、缩放、高亮、观察取消、本地失败与重试 | 引用与续读优先级、云端重新获取研究 |

已发布数值用于坐标与比例的几何计算属于展示；重新计算利润、派息等正式财务结果不属于展示。

## 状态放在哪里

Reader 持有当前场景、焦点、模式、关联目标和返回来源。展示持有实际尺寸、滚动偏移、缩放、平移及 PDFKit 加载状态。

同图换焦点调用 Reader 原地更新；全屏与内嵌使用同一语义焦点，关闭后不能用旧快照覆盖新选择。恢复本设备精确来源时，视口按来源访问身份保存，不能仅按场景保存一个“最后视口”，否则多次访问同一图会互相覆盖。

核心输出返回来源的访问身份和语义位置；本机视口提示可随来源交回但由展示解释。跨设备以内容锚点与物理页恢复，不套用另一尺寸设备的像素坐标。

## 共用观察与关闭契约

展示在内容已显示后，向核心回报有效观察身份、内容位置及变化原因。cause 仅表达用户交互、程序定位或恢复事实，由核心决定是否更新阅读记录。

- PDFKit 任意 page-change 通知不能一律当作用户翻页；适宽、初次定位、恢复、显式翻页和用户手势需要区分。
- 同一内容可能短暂有新旧宿主同时存在，遮挡或退出的旧宿主停止回报，核心继续校验观察是否有效。
- 原生返回手势或弹层关闭只有在确认完成时交回，携带呈现访问身份；取消手势不返回，迟到关闭不重复弹出新的来源。
- 共用宿主的 `dismissPresentation(token)` 接入复用 Reader 的导航规则；不再维护一份可自行修改的 SwiftUI 业务历史。
- 程序恢复可以移动画面，但不伪装为新的实际阅读；真正主动回看即使停在相同锚点仍可更新时间。

这些接入只在共用阅读宿主、图形全屏宿主和 PDFKit 适配中实现，普通业务页面不用各写保存、取消和回调防护。

## PDF 的可观察行为

Reader 交付当前版本的本地文件、来源身份、一基物理页、总页数及可选定位文本。PDFKit 适配内部换算为零基索引，印刷页码仅作说明。

引用与续读政策沿用 Reader 契约：初次引用定位保留续读，主动浏览更新续读。展示只报告事实，不维护另一份续读表。

文件、文档或目标页无法打开时，共用 PDF 宿主显示可重试状态并保持返回来源。高亮文字未匹配不等于整份有效 PDF 失败，仍可显示目标原页和定位提示。本地重试重建同一版本、原件和目标的加载尝试；若确需重新获取资料，交给研究库既有准备能力。

每次加载尝试与当前呈现身份绑定，旧通知和已取消加载不会更新新页面。读取最新研究或改写版本不是 PDF 重试的副作用。

## 参考样式怎样保留

沿用黑白与暖纸色、衬线标题、清楚文字层级、细线图形、克制留白和明确的主要动作。共用具体主题与样式定义即可，不先建立主题插件体系。

主阅读采用自然高度和纵向内容，避免用屏幕高度预算强行缩小整图。复杂图保持标签和点击对象可用，并可全屏放大；多趋势需给出系列标签、单位和期间，关系性质与未知保持可辨认。

## 从当前参考改什么

- `VisualStudyReader.sceneLayout` 当前按屏高分配约 125–260 的图高，`StudyDiagram` 再整体缩放。展示重构应集中在自然尺寸和布局，不复制到每个场景。
- 当前图解与报告有两个 PDF 页面外壳，底层已共用 `NativePDFReader`；集中外壳的加载、错误、控制与关闭契约，保留可用的原生适配。
- 当前图解计算输入打开所有依据页中的第一处；新内容投影提供完整引用列表，由展示呈现全部可选来源。现有依据页本身已支持多个原页，不能误判为所有入口都只支持第一页。
- 当前 PDF 初次定位和页变化共用一个回报，需集中补充原因、加载尝试及取消识别，不能让每个入口另写判断。

## 验收与修改落点

样式改共用具体主题，图形几何改图形呈现，长文与引用列表改共用详情，PDF 加载和观察改原生宿主；修改这些呈现方式不需要重写记录排序与导航政策。

需在后续实现中验证窄屏与较大字体、长关键未知、多输入多来源、密集图与全屏、原页首末页、坏文件和重试、无匹配高亮、过期回调，以及关闭或返回后的精确来源。在真实 iPhone/iPad 验收滚动、点击和缩放手势；本轮仅完成契约和源码核对，未执行这些测试。

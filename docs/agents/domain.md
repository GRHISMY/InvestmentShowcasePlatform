# Domain Docs

本项目采用 single-context，共用一套领域术语与架构决策记录。

## 阅读规则

探索或修改代码前，若根目录 `GLOSSARY.md` 存在，先阅读其中的领域术语；再阅读 `docs/adr/` 中与当前任务有关的架构决策。

这些文件或目录尚不存在时，直接继续工作，不报告缺失，也不预先建议创建。通过 `/domain-modeling` 明确术语或形成实际决策后，再按需创建。

## 目录约定

- `README.md`：项目流程、结构、数据来源、当前实现与待定义事项。
- `GLOSSARY.md`：后续按需建立的领域术语与概念关系。
- `docs/adr/NNNN-<decision-slug>.md`：后续按需记录的架构决策。

流程事实以 README 为准，领域术语以 GLOSSARY 为准，已记录决策以对应 ADR 为准；通过路径引用相关说明，避免在多处重复维护正文。

## 使用领域词汇

在任务标题、重构建议、假设和测试名称中，使用 `GLOSSARY.md` 已定义的术语，遵循其明确排除的同义词约定。

需要的概念尚未定义时，先检查是否引入了项目不用的说法；确有缺口时，记录为后续 `/domain-modeling` 的输入。

## 决策冲突

建议与既有 ADR 冲突时，明确引用该 ADR，并说明需要重新讨论的原因。

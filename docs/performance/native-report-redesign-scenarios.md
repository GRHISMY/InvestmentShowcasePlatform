# 完整报告原生重做的固定场景（#22 → #25）

本页固定 #22 实现的实际用户路径，供 #25 在同一真实 iPhone 上按 #19 冻结预算测量。它不改变 [v1 性能预算](native-report-budget-v1.json)，也不代表性能问题已经定位或解决。正式 `Study` 文件未修改；使用完整 r4 格力研究（2020—2025 全年及 2026 年前九个月，资料截至 2026-11-09），保留 25 条判断、5 个维度、13 项监测与全部原始 PDF。

## 固定实现

报告继续使用原生 `ReadingScrollView` / `ReaderScroll` 的实际布局、可见性授权、语义锚点和本机偏移恢复。全文采用系统字体、连续系统背景与正文行距；计算、依据是正文内的局部入口。所有正文与远处锚点都保留在文档布局中，不使用无法在当前固定 hosting 文档中保证远处锚点存在的 `LazyVStack`。该选择保证完整跳转与恢复，并不提供帧耗时改善证据；#25 需要根据真机结果决定是否进一步替换排版策略。

目录为原生可搜索列表，含 50 个真实目标：摘要、5 个章节、25 条判断、整份研究限制、5 个维度及13项监测。目标与不透明链接由 Reader 提供，页面不创建另一套路由。关闭目录不产生阅读导航；点击条目后由 Reader 接受来源、目标与观察授权。

## 固定用户路径

1. 在研究库打开同一完整正式版本，进入“报告” Tab。打开“目录”，搜索“完整研究摘要”并点击结果，检查公司标题、报告摘要、覆盖期间、资料截止日和底部原生 Tab。进程冷进入和热切换的条件仍按 #19 文档分别固定。
2. 打开目录，依次搜索并点击以下完整标题，直到标题与紧接的正文可读：
   - “先分清利息记在哪里，再看产品生意赚了多少”（`gree-profit`）。
   - “最近一个季度，利润降得比销售金额快得多”（`gree-latest-quarter`）。
   - “2026年销售收款减少，收回贷款补了一部分”（`gree-2026-cash-drivers`）。
   在已经非零滚动的位置重复跳转。目录准备、搜索和等待列表稳定在 tap-to-accessibility 采样区间之外；区间仍从点击真实目标条目开始，到目标正文可读为止。真实首个已呈现帧仍须 Instruments/屏幕证据，不能以代理计时替代。
3. 在第一项正文处按 #19 的相同相对视口手势，连续快速滚动30秒、暂停2秒、再滚动15秒。保留全部正文，不重置语义位置或以节选降低工作量。
4. 在现金判断正文滚至计算入口，打开计算，再打开首个输入的依据及原始 PDF；关闭后返回原判断的实际来源位置。再选择“销售收款减少，贷款回收补了一部分。”的“只看销售收回的钱”关联，确认图解 Tab 高亮、焦点正确；“回到刚才”恢复报告真实偏移。普通图解/报告 Tab 切换各自恢复自己的位置。
5. 在最近一季度判断末尾保留所有已声明的相关图解选择；该正式判断有7个位置，不能自动任选一个。`gree-profit` 无关联图解时明确显示“这条判断暂无关联图解，可继续核对计算与依据。”，不生成链接。
6. 从远处正文用目录进入第一项监测“继续查用户实际买了多少、维修结果怎样，以及经销商手里还有多少没卖出的货。”，检查“状态：待核对”和“何时跟进：相关事件发生时”。未知状态与触发值按原文显示；旧包未提供触发值时不编造。
7. 使用系统大字体重复最近一季度的标题与长正文场景，核对左右边界、安全区域、目录、返回和三个 Tab 可用。大字体为功能/排版场景，默认性能比较仍保持 #19 的同一默认字号。

## 验证边界

#22 的 Core 回归读取完整正式 `research.json`，逐项核对所有判断正文、限制、反证、未知、关联事实、维度与监测文字及身份；另覆盖目录目标、来源偏移、一对多关联与普通方式恢复。原生 UI 回归使用同一完整包与真实控件，覆盖缺失关联、远处目录重定位、取消目录、监测状态、系统大字体及相关阅读返回。

本轮 #22 开发验证仅在模拟器进行。真实 iPhone 的首屏、长正文、目录、关联返回演示及 #25 的帧时延/卡顿采样仍须单独完成；iPad、模拟器与 Mac 结果均不能代替。#19 的 iPhone 14 基线当前仍受开发 App 证书信任阻塞，未获得有效样本。不得把本页或自动化成功解释成原症状手机已经复现、已经测量或性能已经达标。

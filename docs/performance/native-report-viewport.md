# 完整报告原生视口修复

本记录说明 #25 的实现及原生回归证据。真机反馈与冻结验收口径仍以 [iPhone 14 基线](2026-11-17-iphone14-app-trace.md)、[性能基线](native-report-baseline.md) 和 `native-report-budget-v1.json` 为准；本文的原生布局检查不能替代真机首个实际呈现帧、hitch 和完整样本分布。

## 已确认的问题与修改

旧版正常 App 的首次报告作用域包含约 1.4 秒 CA layout/display，主要经过完整报告的嵌套 VStack、Text 和自然尺寸计算。生产报告适配器上的失败回归使用完整正式研究：摘要可读首屏到达时，52 个 authored blocks 全部已经布局，最后一项监控也已布局。

`ReportDocumentView` 现在拥有报告专用的 UICollectionView 视口，按需实现当前报告行。52 个 authored blocks、全部正文、事实、计算/依据/关联动作和原有语义锚点都保留；无锚点的索引标题作为前一原生行的尾部内容，以保持原来的来源归属。每条判断之前的 14 点空隙同样属于前一来源，总间距与正文坐标不变。

可见行使用各自的 UIHostingController，保留旧文档的 `safeAreaRegions = []` 和自然纵向尺寸约束。外部可行性检查曾证明 UIHostingConfiguration 的行高会随安全区位置改变；另一个失败回归证明，缺少自然纵向尺寸约束会使正文在暂时的估算行高中压缩或居中。这两种情况都会破坏真实来源坐标。

每个阅读激活期中的内容与不透明动作保持稳定，持续更新最新观察回调。新的激活/可见期更新内容与 scope；旧队列工作按 scope ID 取消。宽度或文字环境重排保留已稳定的语义锚点与局部偏移，等待实际 marker 几何稳定后恢复，不生成新的阅读事件。尚未到达的定向目标优先于临时首屏几何；真实用户滚动可以取消尚未完成的恢复，并先确认实际到达，再接收浏览观察。

研究关系、位置合法性、来源链、阅读时间和记录接受规则继续由 Reader 管理。图解、计算/依据和 PDF 使用原来的通用滚动行为；共用 marker 类型只调整模块内可见性。

## 原生回归

回归在真实 UIWindow 中使用正式完整研究及生产报告 builder。布局工作和坐标由 fixture 自己的 UIView marker 测量；窗口坐标断言容差为 1 点；它们不读取私有缓存，也不使用 Core 计时代替原生 UI。

- 首屏工作：旧 eager 适配器观测到 52 个正文布局，违反 `<12` 的工作界限；新视口通过，末项监控可在之后到达，首屏无需布局它。
- 真实坐标：远端非标题部分 +23 点、来源 +37 点、末项监控→摘要、计算动作间隙及返回来源均有独立窗口坐标检查。
- 反向进入间隙：索引标题曾错误保存为后面的 dimension，返回约漂移 50 点；判断前的空隙曾错误保存为摘要。修复后保存前一正式锚点并准确返回。
- 纯宽度/AX：390→280 点只改变 UIKit bounds，fixture 来源曾从 −37 漂到 −47 点。修复后保持来源坐标；AX XXXL 与停止/重开后的旧 scope 取消也通过。
- 到达中的事件：环境更新曾把尚未实现的远端目标替换为摘要；真实原生滚动曾从约 −456 点被拉回 0 并丢掉浏览事件。对应失败→通过回归保留了目标优先级、用户接管及 arrival→browsing 顺序。

18 项原生 host 检查（12 report + 6 generic scroll）、156 项 Core/workspace 检查及 15 项实际 App 导航/查证/来源返回检查通过。Debug 原生构建及未安装的 unsigned generic-device Release 构建通过。集合视口通过稳定标识 `report-document` 驱动，同样的手势不再假定报告一定是 XCUI 的 ScrollView 类型。

## 验收边界

目前这些证据证明原生工作量与位置/观察行为，未宣布冻结的真机性能预算通过。候选必须与旧版在同一台已授权 iPhone 14、同一配置和完整内容、相同运行条件下比较。该设备不是最初报告症状的 iPhone 18 Pro。完整 Debug/Release 首帧及滚动矩阵、双设备云交付验收仍需各自的实际结果；不因此关闭 #19/#25。

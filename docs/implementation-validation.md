# 实施验证契约

用户已确认技术方案及十二项实施切片，并指定使用 Codebase Design 与 TDD。任务、依赖和完成证据以 [GitHub 技术方案的子任务](https://github.com/GRHISMY/InvestmentShowcasePlatform/issues/4) 为准。

以下整理已确认方案中的测试 seam。测试从调用者可见的 Interface 进入，不检查内部对象调用顺序，也不为每个辅助类型另建测试入口。

| 已确认的 seam | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 已发布研究的载入与固定资源访问 | 正式身份、研究与阅读绑定、清单和原件字节一致；不同版本不会串用同名 PDF | PDFKit 实际解析、手势与页面布局 |
| Mac 公开分发操作与命令入口 | 正式成果可分发、版本不可变、旧版保留、失败不破坏已发布内容 | iCloud 的实际文件到达顺序 |
| `StudyReader` 的阅读视图及具名动作 | 跳转、返回、模式恢复、引用与续读、过期观察和有效位置恢复 | SwiftUI 的滚动几何与原生关闭手势 |
| `StudyShelf` 的研究条目、打开结果与记录状态 | 完整准备后才可读、继续原版本、打开请求替代、可靠保存与候选选择 | 设备目录授权及真实网络条件 |
| `CloudFolder` 系统适配 | 用可控外部条件验证缺件、授权失败、迟到响应和记录交换；本机部分使用真实临时目录 | 两台真实设备之间的 iCloud 交付时延 |
| 共用展示与 PDFKit 宿主 | 可见位置原因、物理页、加载重试、取消、字体与操作可用性 | 真机签名、设备信任及双设备集成验收 |

每轮只增加一个尚未满足的行为：先运行并记录预期失败，再实现足以通过的代码，然后进入下一行为。预期结果来自已确认规格、正式样本或独立算例，不从实现反算。内部整理放在行为通过后的审查阶段。

每个任务完成时记录适用的测试、构建和实际设备结果；未执行的真机检查不能记为通过。已替换分支的旧导航或记录规则在同一任务内移除，单向迁移读取除外。
